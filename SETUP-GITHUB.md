# Налаштування: хмарний запуск + веб-дошка

Що ти отримаєш:

- програма сама перевіряє Immoweb і Zimmo кожні 6 годин (комп'ютер може
  бути вимкнений);
- **веб-дошка** зі списком усіх оголошень, із фото: клікнув на
  оголошення — воно стає сірим («переглянуто»), є фільтр «тільки нові»;
  якщо та сама квартира є на обох сайтах — картка одна, з посиланням
  «також на …»;
- позначка **«⚡ оптика Proximus»** на картках, де за адресою є
  оптоволоконний інтернет;
- лист приходить короткий: «N нових» + посилання на дошку, і це
  посилання одразу показує лише ці нові оголошення (а не всю історію);
- критерії пошуку (ціна, місто, тип житла тощо) можна міняти формою на
  вкладці Actions, без редагування файлів.

Усе безкоштовно. Git встановлювати не треба — усі файли завантажуються
через звичайний сайт GitHub.

---

## Важливо: репозиторій має бути публічним

Безкоштовний GitHub показує веб-сторінки (нашу дошку) лише з публічних
репозиторіїв. Щоб при цьому пошта не була видна стороннім, її адреса
**не пишеться в `config.yaml`** — вона задається окремо, через «секрети»
GitHub (це й безпечніше). Секретів буде три — див. крок 5.

## Крок 1. Створити репозиторій

1. <https://github.com/new>
2. **Repository name:** `real-estate-aggregator`
3. Обери **Public**
4. Більше нічого не додавай → **Create repository**

## Крок 2. Завантажити файли

**Add file → Upload files**, перетягни з
`C:\Users\zetsu\Desktop\real-estate-aggregator`:

- тека `aggregator`
- тека `tests`
- тека `docs`      ← сторінка-дошка
- тека `scripts`   ← нова, скрипт для форми зміни критеріїв
- `config.yaml`
- `main.py`
- `requirements.txt`
- `README.md`
- `.gitignore`
- `.env.example`

**НЕ завантажуй:** `.env` (там пароль і адреса), `.venv`, `listings.db`,
`aggregator.log`, `run-aggregator.ps1`.

Внизу — **Commit changes**.

## Крок 3. Створити файл автозапуску

Тека `.github` на Windows прихована, тож зробимо файл на сайті:

1. Вкладка **Actions** → **set up a workflow yourself**.
2. Зітри весь текст, встав вміст файлу `.github/workflows/check.yml` з
   проєкту (відкрий у редакторі, скопіюй повністю).
3. **Commit changes**.

## Крок 4. Дозволити автозапуску запис у репозиторій

Без цього дошка не оновлюватиметься (програма не зможе зберегти
`docs/data.json`).

1. **Settings** → зліва **Actions** → **General**
2. Прокрути до розділу **Workflow permissions**
3. Обери **Read and write permissions** → **Save**

## Крок 5. Додати три секрети

**Settings** → **Secrets and variables → Actions** → **New repository
secret**, і так тричі:

| Name | Secret (значення) |
|---|---|
| `AGGREGATOR_SMTP_USERNAME` | `nastya.ignatenko.2003@ukr.net` |
| `AGGREGATOR_EMAIL_TO` | `nastya.ignatenko.2003@ukr.net` |
| `AGGREGATOR_SMTP_PASSWORD` | пароль для зовнішніх програм ukr.net |

## Крок 6. Увімкнути веб-дошку (GitHub Pages)

1. **Settings** → зліва **Pages**.
2. **Source:** *Deploy from a branch*.
3. **Branch:** `main`, тека **`/docs`** → **Save**.
4. Через ~1 хвилину вгорі з'явиться адреса виду
   `https://ТВІЙ-ЛОГІН.github.io/real-estate-aggregator/` — скопіюй її.

## Крок 7. Вписати адресу дошки в конфіг

1. У репозиторії відкрий `config.yaml` → олівець **Edit**.
2. Знайди в кінці:
   ```yaml
   webpage:
     enabled: true
     output_dir: docs
     url: ""
   ```
3. Встав свою адресу в лапки:
   ```yaml
     url: "https://ТВІЙ-ЛОГІН.github.io/real-estate-aggregator/"
   ```
4. **Commit changes**.

## Крок 8. Перший запуск і перевірка

1. **Actions** → **Перевірка нових оголошень** → **Run workflow**.
2. За 1–2 хвилини — зелена галочка.
3. Перевір пошту: має прийти лист із посиланням на дошку.
4. Відкрий дошку — там список усіх оголошень.

Якщо запуск **червоний** — відкрий журнал, скопіюй останні рядки, покажи мені.

## Як користуватись дошкою

- **⚙ Змінити критерії** — вгорі дошки, поруч із фільтрами. Веде прямо
  на форму GitHub Actions (крок 8 вище) — не треба шукати вкладку
  Actions самій. Спрацює лише якщо ви ввійшли в той самий акаунт
  GitHub, яким створювали репозиторій.
- Кожна картка тепер показує **фото** оголошення (якщо сайт його дав) —
  клік по фото відкриває оголошення так само, як і кнопка нижче.
- Якщо ціна на сайті змінилась відколи оголошення вперше з'явилось —
  картка показує бейдж **⬇ було X€** (знижена) або **⬆ було X€**
  (підвищена).
- **Відкрити на Immoweb / Immovlan** — відкриває оголошення в новій
  вкладці й автоматично позначає його переглянутим (сіріє).
- **Позначити переглянутим / Повернути в нові** — вручну.
- **Тільки непереглянуті** — сховати вже переглянуті.
- **Позначити всі переглянутими** — коли хочеш почати «з чистого аркуша».
- Випадаючий список сортування — **спочатку нові** (за замовчуванням),
  **дешевші спочатку** або **дорожчі спочатку**.
- **📍 На карті** — кнопка на кожній картці, поруч із «Відкрити на
  Immoweb». Відкриває Google Maps у новій вкладці на точній адресі
  квартири (вулиця + номер будинку — Immoweb дає її майже завжди). Якщо
  в оголошенні адреси немає, кнопка називається **📍 Місто на карті** й
  показує лише населений пункт.

Позначки «переглянуто» зберігаються в тому браузері, де ти дивишся. Якщо
ввійти через Google (кнопка «Вхід» вгорі) — вони додатково
синхронізуються між пристроями: те, що позначено на телефоні,
з'явиться позначеним і на ноутбуці (з невеликою затримкою, за кілька
секунд після зміни).

## Що відбувається саме собою

- Кожні 6 годин GitHub запускає перевірку.
- Нові оголошення → лист + оновлення дошки.
- Після кожного запуску GitHub сам робить коміт `Оновлення бази й дошки`
  (від `github-actions[bot]`) — так зберігається пам'ять і не вимикається
  розклад. Це нормально, чіпати не треба.

## Якщо щось міняти

- **Критерії пошуку** — найпростіше через форму: вкладка **Actions** →
  «Перевірка нових оголошень» → **Run workflow** → заповніть потрібні
  поля (ціна, місто, тип житла тощо), решту лишіть порожньою → **Run
  workflow**. Програма сама перепише `config.yaml` і одразу перевірить
  сайти з новими критеріями. Можна й напряму — `config.yaml` на сайті
  (олівець Edit → Commit), кому як зручніше.
- **Розклад** — рядок `cron` у `.github/workflows/check.yml`.
- **Пароль пошти зміниться** — онови секрет `AGGREGATOR_SMTP_PASSWORD` і
  локальний файл `.env`.

## Можлива проблема

Immoweb за захистом Cloudflare. Якщо запуск впаде з `403` / `Forbidden` —
напиши, підберемо обхід або повернемось до варіанту «пристрій, що завжди
ввімкнений».

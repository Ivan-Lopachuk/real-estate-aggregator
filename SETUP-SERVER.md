# Налаштування AI-чату (сервер на Render + OpenRouter)

Що ти отримаєш: панель чату збоку від дошки, куди можна написати,
наприклад, «квартира в Антверпені, від 30 м², до 700€, район
Мерксем» — і за кілька секунд прийде список реальних оголошень з
Immoweb і Immovlan.

Безкоштовно (Render, безкоштовний рівень), крім самих запитів до AI —
OpenRouter бере невелику суму за кожне повідомлення в чаті (ти сама
поповнюєш баланс, скільки хочеш).

---

## Як це працює (коротко)

Дошка (`docs/index.html`) — статична сторінка, вона нічого сама не
рахує. Щоб чат міг прямо зараз запустити пошук і повернути відповідь,
потрібен окремий маленький сервер — `server/app.py` із цього ж
репозиторію. Дошка звертається до нього через інтернет.

Захист: сервер знає секретний **код доступу**. Кожен, хто хоче
скористатись чатом (ти або той, кому ти даси код), уводить цей код
один раз у браузері. Без правильного коду сервер відмовляє — тобто
ніхто сторонній не витратить твої гроші на OpenRouter.

---

## Крок 1. Акаунт OpenRouter і ключ

1. Зайди на <https://openrouter.ai> → зареєструйся.
2. Поповни баланс на невелику суму (кілька доларів вистачить надовго
   для особистого використання).
3. **Keys** → **Create Key** → скопіюй ключ (виду `sk-or-...`) —
   знадобиться на кроці 3. Показується лише один раз, тож збережи його
   десь у собі (не в публічний репозиторій!).

## Крок 2. Акаунт Render і сервіс

1. Зайди на <https://render.com> → зареєструйся (можна через GitHub-
   акаунт, яким ти вже користуєшся).
2. **New +** → **Web Service**.
3. Обери репозиторій `real-estate-aggregator` (Render попросить дати
   доступ до GitHub — дозволь).
4. Заповни форму:
   - **Name:** будь-яка назва, напр. `real-estate-chat`
   - **Root Directory:** `server`
   - **Runtime:** Python 3
   - **Build Command:** `pip install -r requirements.txt`
   - **Start Command:** `python app.py`
   - **Instance Type:** Free
5. **Create Web Service** — Render почне збирати й запускати сервер.
   Це займе хвилину-дві.

## Крок 3. Секрети сервера

У щойно створеному сервісі: **Environment** (зліва) → **Add
Environment Variable**, і так двічі:

| Key | Value |
|---|---|
| `OPENROUTER_API_KEY` | ключ з кроку 1 (`sk-or-...`) |
| `ACCESS_CODE` | будь-який код доступу, який ти вигадаєш (напр. `nastya-search-2026`) — саме його вводитимеш у чат |

Необов'язково:

| Key | Value |
|---|---|
| `OPENROUTER_MODEL` | назва моделі OpenRouter, якщо хочеш іншу за замовчуванням (`openai/gpt-4o-mini`) |

Після додавання змінних Render сам перезапустить сервіс.

## Крок 4. Адреса сервера

Угорі сторінки сервісу на Render — адреса виду
`https://real-estate-chat-xxxx.onrender.com`. Скопіюй її.

## Крок 5. Вписати адресу в дошку

1. Відкрий `docs/index.html` на GitHub (олівець **Edit**).
2. Знайди рядок:
   ```js
   var CHAT_BACKEND_URL = "";
   ```
3. Встав туди адресу з кроку 4 **з `/api/chat` на кінці**:
   ```js
   var CHAT_BACKEND_URL = "https://real-estate-chat-xxxx.onrender.com/api/chat";
   ```
4. **Commit changes**.

## Крок 6. Перевірка

1. Відкрий дошку. Зліва (або зверху на телефоні) — панель **🤖
   AI-пошук**.
2. Напиши щось на кшталт «квартира в Генті до 800€» → Enter.
3. Перший раз попросить код доступу — впиши той, що задала на кроці 3.
   Він запам'ятається в цьому браузері.
4. За кілька секунд має прийти відповідь і список оголошень.

**Якщо довго немає відповіді при першому повідомленні** — це
нормально: безкоштовний Render «засинає» після ~15 хв без
використання і «прокидається» до 30-60 секунд на перший запит.
Наступні повідомлення підряд будуть швидкими.

---

## Кому дати доступ

Скажи людині код доступу (`ACCESS_CODE`) — вона введе його при першому
повідомленні в тому самому чаті на дошці. Захотіла забрати доступ —
зміни `ACCESS_CODE` на Render (Environment) на нове значення; старий
код одразу перестане працювати для всіх.

## Якщо щось не так

- **«Чат ще не налаштовано»** — не вписана або невірна адреса в
  `CHAT_BACKEND_URL` (крок 5).
- **«Неправильний код доступу»** — звір `ACCESS_CODE` на Render і те,
  що ввела в чаті.
- **Довго немає відповіді** — почекай хвилину (сервер «прокидається»)
  і спробуй ще раз.
- **Не знайшов оголошень** — можливо, для такого поєднання критеріїв
  їх справді зараз немає, або назву міста написано так, що довідник
  Zimmo її не впізнав — спробуй іншим написанням (напр. англійською чи
  нідерландською назвою міста).

## Вхід через Google (перший крок до майбутньої розсилки)

Це окрема, необов'язкова частина. Зараз вхід нічого не "розблоковує"
на сторінці, крім того, що замість кнопки входу бачиш своє ім'я й
фото — це перший маленький крок більшого плану (пізніше з'явиться
функція "Моя розсилка", доступна лише залогіненим).

### Крок 1. Застосунок у Google Cloud Console

1. Зайди на <https://console.cloud.google.com> → увійди Google-акаунтом.
2. Вгорі створи новий проєкт (**New Project**) — назви як завгодно,
   напр. `real-estate-aggregator`.
3. У пошуку вгорі набери **OAuth consent screen** → відкрий.
   - User Type: **External** → **Create**.
   - Заповни лише обов'язкові поля (назва застосунку, твоя пошта як
     контактна) → **Save and Continue** кілька разів, нічого зайвого
     додавати не треба.
   - На кроці **Test users**: якщо потім не публікувати застосунок —
     додай сюди пошти людей, кому даси доступ. Якщо натиснеш
     **Publish App** — увійти зможе будь-хто з Google-акаунтом.
4. У пошуку набери **Credentials** → **Create Credentials → OAuth
   client ID**.
   - Application type: **Web application**.
   - **Authorized JavaScript origins → Add URI** → встав адресу своєї
     дошки БЕЗ шляху в кінці, лише домен, напр.
     `https://твійлогін.github.io`.
   - **Create**.
5. З'явиться **Client ID** (виду
   `123456789-abc...apps.googleusercontent.com`). Це не секрет — можна
   вставляти прямо в код сторінки.

### Крок 2. Client ID на Render

**Environment → Add Environment Variable**:

| Key | Value |
|---|---|
| `GOOGLE_CLIENT_ID` | Client ID з кроку 1 |

### Крок 3. Той самий Client ID у дошку

1. Відкрий `docs/index.html` на GitHub (олівець **Edit**).
2. Знайди рядок:
   ```js
   var GOOGLE_CLIENT_ID = "";
   ```
3. Встав туди Client ID:
   ```js
   var GOOGLE_CLIENT_ID = "123456789-abc...apps.googleusercontent.com";
   ```
4. **Commit changes**.

### Крок 4. Перевір

Відкрий дошку, зроби Ctrl+F5. Угорі праворуч у кольоровій шапці має
з'явитись кнопка **Sign in with Google**. Увійди — кнопка має
замінитись на твоє ім'я, фото й кнопку "Вийти".

**Якщо кнопка не з'явилась** — перевір, що `GOOGLE_CLIENT_ID` вписаний
однаково і в `docs/index.html`, і на Render, і що домен дошки точно
доданий в **Authorized JavaScript origins** (крок 1, без хибодруку і
без `/` в кінці).

## Розсилка (крок 2): збереження налаштувань у GitHub

Після входу через Google з'являється кнопка **✉ Розсилка** — форма з
критеріями пошуку, інтервалом і поштою. Щоб сервер міг її
"запам'ятати" назавжди (сам він нічого не зберігає між
перезапусками), йому потрібен окремий токен із правом **записувати**
у твій репозиторій. Кожен збережений профіль лягає туди файлом
`profiles/<id>.json`.

### Крок 1. Fine-grained токен GitHub

1. GitHub → фото профілю праворуч вгорі → **Settings**.
2. Ліворуч унизу: **Developer settings**.
3. **Personal access tokens → Fine-grained tokens → Generate new
   token**.
4. Заповни:
   - **Token name:** будь-яка, напр. `real-estate-subscriptions`.
   - **Expiration:** онови ближче до цієї дати, коли термін вийде
     (GitHub сам попередить поштою) — це нормально для токена, який
     довго живе на сервері.
   - **Repository access → Only select repositories** → обери
     `real-estate-aggregator`.
   - **Permissions → Repository permissions → Contents** → постав
     **Read and write**.
5. **Generate token** → скопіюй значення (виду `github_pat_...`).
   Показується лише один раз — якщо загубиш, доведеться створити
   новий.

### Крок 2. Змінні середовища на Render

**Environment → Add Environment Variable**, і так двічі:

| Key | Value |
|---|---|
| `GH_WRITE_TOKEN` | токен з кроку 1 |
| `GH_REPO` | `твійлогін/real-estate-aggregator` |

### Крок 3. Перевір

1. Відкрий дошку, увійди через Google.
2. Натисни **✉ Розсилка** → заповни форму (місто, ціна, інтервал,
   пошта) → **Зберегти розсилку**.
3. Має з'явитись зелене "Збережено!".
4. Перевір на GitHub: у репозиторії з'явилась папка `profiles/` з
   файлом виду `109876543210123456789.json` — це твій профіль.

**Важливо:** саме надсилання листів за цими профілями поки що НЕ
підключене — це наступний, окремий крок. Зараз форма лише зберігає
налаштування.
